# Linting Rules

Lint is CLI-first. `llm-wiki lint --json` is the source of truth for every
check in the rules table below; the agent runs it first and spends judgment only
on the rows with an Agent duty and on reviewing what `--fix` proposes. Exact
flags are in [cli.md](cli.md). What each check detects, the placement map, the
alias tables (C13) and the maintenance rationale are in the catalogue
[lint-rules.md](lint-rules.md).

## Running the CLI

```bash
llm-wiki lint --json [<wiki-root> | --local | --wiki <slug>] [--hub <path>] \
  [--private | --public] [--include-archived] [--fix] \
  [--fail-on critical|warning|suggestion] [--strict-engine] \
  [--profile citations,datasets] [--github-annotations] [--max-warnings N]
```

- `--fail-on` sets the lowest severity that exits non-zero (default
  `suggestion`, any finding). `--strict-engine` turns declared-versus-running
  engine drift from a warning into critical. `--include-archived` is required to
  lint an explicitly targeted archived topic.
- `--profile` adds C26 `citations` and C27 `datasets`; `--github-annotations` prints `::error|warning|notice` commands (stderr with `--json`); `--max-warnings N` exits 1 above N warnings. Not with `--all`.
- The report holds `status`, `counts`, `fixes` and `issues[]` (`check`,
  `fix_class`, `severity`, `message`, `path`, `fixable`). `check` is the id of
  the row below that found the issue; match findings by `check` and `path`, not
  by message.
- Non-zero with JSON: findings met `--fail-on`; without: a CLI error (bad flags,
  unresolved or archived wiki).

## Fix classes

Classes: `quarantine` C12, `placement` C11, `frontmatter` C2/C4b/C6/C13/C15,
`index` C3, `create` C1/C6/C22, `registry` C19, `gitignore` C19/C21, `log`
log.md. Held back: reported as without `--fix`.

| Flag | Effect |
|---|---|
| `--preflight` | No writes; `plan[]`; exit 0 unless `--fail-on` |
| `--fix-only C,...` | Only these; implies `--fix` |
| `--no-quarantine`, `--no-log` | Drop that class |
| `--refuse-on C,...` | One would act: exit 2, no writes |

The plan reads the tree as it is: a repair that only becomes necessary after an
earlier repair is not listed, and under `--refuse-on` it is refused when
reached, after earlier classes have written.

## Severity

- **Critical**: broken functionality (missing indexes, wrong placement, bad frontmatter,
  privacy)
- **Warning**: inconsistency (dead links, bad sources, stale dates)
- **Suggestion**: improvement (coverage, connections, migrations)
- **Info**: never fails a wiki

## Rules table

**Fix** = changed by `--fix`; a dash means report only. **Agent** = judgment or a
check the CLI does not implement yet. The CLI detects every row except C7; the
report's `message` says what it found, and `lint-rules.md` says what each check
detects.

| Check | Sev | Fix | Agent |
|---|---|---|---|
| C1 Structure | Crit | Create dirs, indexes, `inbox/`, starter `schema.md` | Absent `inventory/` or `datasets/` is a suggestion, never created for lint |
| C2 Frontmatter | Crit/Warn | Wiki articles only: infer `category`, `summary`, dates, `tags` (theses), `volatility: warm` | Spot-check `compiled-from` and collection keys (`collection`, `adapter`, `upstream_id`, `revision`, `sha`, `canonical_url`, `fetched`) |
| C3 Index consistency | Warn | Generated or stub index (carries `Generated by local llm-wiki lint`, or only headings): regenerate by directory contract; stale rows alone are refreshed in place, after the frontmatter repairs. Hand-curated index: repair in place — append missing entries, remove only a list item or table row whose local links are all dead, keep every other line and its order | Update drifted statistics and the "Last compiled" and "Last lint" dates |
| C4 Link integrity | Warn | - | Add the reverse link where it makes sense |
| C4b Source provenance | Warn | Rewrite a fuzzy ref to the exact `raw/...md` path when exactly one file matches | Ambiguous refs; never remove provenance |
| C5 Tag hygiene | Warn | - | Semantic near-duplicates; index/frontmatter tag drift; propose the canonical tag |
| C6 Coverage | Sugg | Attach the pointer to that article; otherwise write `wiki/references/uncompiled-source-coverage.md` | Decide: compile, backlog, or retire; articles with overlapping tags lacking `See Also` |
| C7 Deep (`--deep`) | Sugg | - | WebSearch spot-checks, newer information, stale sources (ingested over 6 months, not recompiled), new connections |
| C8 Projects | Crit/Warn/Sugg | - | **C8c** `project migrate-why` (rule below); review stale members |
| C9 Project candidates | Info (rules/3) | - | Turn a candidate into a ready-to-paste `wiki project new` + `add` block. Never auto-move |
| C11 Placement | Crit | `mv` to the canonical path; skip on collision | Hub-level content directories: warn, never delete |
| C12 Unknown files | Warn | Files move to `inbox/.unknown/`; directories warn only | - |
| C13 Aliases | Warn | Rewrite the legacy key or value to canonical (class `frontmatter`) | Warn on unknown keys |
| C14 Freshness | Warn/Info | - | Rank with `llm-wiki freshness score --json` (composite 0-100 against `freshness_threshold`); narrative; suggest `wiki refresh` |
| C15 Volatility | Info | Add `volatility: warm` | - |
| C16 Inventory | Sugg | Missing indexes of existing layers; never create the tree | Judge each candidate's fit before suggesting its `migrate-output --dry-run`; never convert |
| C17 Datasets | Sugg | Missing indexes of existing layers; never create the tree | As C16, with `wiki dataset migrate-output`; never convert |
| C18 Missing sources | Warn | - | Suggest recompiling the raw source, or `compiled-from: conversation`; never add either |
| C19 Archive and registry | Warn/Crit | Portable paths; append `topics/**/*-PRIVATE/` to `.gitignore` | Decide which copy of a colliding slug stays (never choose); filesystem-only archived topics (use `llm-wiki archive list`); active content citing archived paths |
| C20 Source lifecycle | Crit/Warn | - | Move each source into its topic or set `source_store` explicitly |
| C21 Tracked machine state | Info (rules/3) | Hub: append the missing rules to `.gitignore` | Tracked files: `git rm --cached` after the owner agrees |
| C22 Engine and rule set | Warn/Crit | Declare the current rule set in an undeclared `config.md` | - |
| C23 Specialists | varies | - | - |
| C24 Hub index | Info | - | `hub index --write` |
| C25 Private tracked | Crit | - | `git rm --cached` |
| C26 Citations (`--profile`) | Info (rules/3) | - | - |
| C27 Dataset payloads (`--profile`) | Info (rules/3) | - | - |

Wiki-links and footnotes report as `C4`. C7 is agent-only; C10 is
unassigned.

## Whole-tree checks

C4 reads `wiki/` and `inventory/`; `links check` covers the rest of a tree,
`lint --all` every hub root.

## C8c: legacy `_project.md` to `WHY.md` (CLI, with `--fix`)

`llm-wiki project migrate-why [--apply] --json` is the rule: lossless (title
and goal from frontmatter, derived Members sections dropped, the rest kept in
order), idempotent once `WHY.md` exists, never a placeholder goal. Preview it,
then `--apply` with `--fix`; report each `Migrated ... (preserved N sections)`.

## Semantic passes

- **Coverage**: group the CLI's uncovered and orphan findings by topic,
  recommend compile, `See Also` link or backlog, and name the articles that
  should link. A backlog entry is not a synthesized source.
- **Freshness**: rank flagged articles by `freshness score`; warn for hot and
  warm, info for cold.
- **Deep**: cite what a search found; never rewrite bodies.

## Fix review

Apply only unambiguous fixes. Never rewrite bodies, create `WHY.md`
placeholders, move files into projects, convert outputs to inventory or dataset
records, delete unknown directories, create an absent inventory or dataset tree,
resolve slug or archive collisions, add `compiled-from: conversation`, or move a
topic in or out of the archive.

## Report

Lead with plain English, not a check code (it may trail in parentheses).

```markdown
## Wiki Lint Report - YYYY-MM-DD
### Summary  (checks run, critical/warnings/suggestions, auto-fixed)
### Critical Issues / Warnings / Suggestions  (description - path)
### Coverage  (uncovered sources, broken links, missing See Also)
### Projects and Candidates  (missing WHY.md, stale, migrated, groupings)
### Inventory and Datasets  (counts, schema issues)
### File Placement and Schema  (moves old -> new, quarantined files)
### Archive  (checked topics, registry repairs, collisions)
```
