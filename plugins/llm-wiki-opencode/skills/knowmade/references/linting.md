# Linting Rules

Lint is CLI-first. `llm-wiki lint --json` is the source of truth for every check
marked **CLI** below; the agent runs it first and spends judgment only on the
rows marked **agent** and on reviewing what `--fix` proposes. Exact flags are in
[cli.md](cli.md).

## Running the CLI

```bash
llm-wiki lint --json [<wiki-root> | --local | --wiki <slug>] [--hub <path>] \
  [--private | --public] [--include-archived] [--fix] \
  [--fail-on critical|warning|suggestion] [--strict-engine] \
  [--profile citations,datasets] [--github-annotations] [--max-warnings N]
```

- `--fail-on` sets the lowest severity that exits non-zero (default
  `suggestion`, any finding). `--strict-engine` turns declared-versus-running
  engine drift from a warning into critical. `--include-archived` is required to
  lint an explicitly targeted archived topic.
- `--profile` adds C26 `citations` and C27 `datasets`; `--github-annotations` prints `::error|warning|notice` commands (stderr with `--json`); `--max-warnings N` exits 1 above N warnings. Not with `--all`.
- The report holds `status`, `counts`, `fixes` and `issues[]` (`check`,
  `fix_class`, `severity`, `message`, `path`, `fixable`). `check` is the id of
  the row below that found the issue; match findings by `check` and `path`, not
  by message.
- Non-zero with JSON: findings met `--fail-on`; without: a CLI error (bad flags,
  unresolved or archived wiki).

## Fix classes

Classes: `quarantine` C12, `placement` C11, `frontmatter` C2/C4b/C6/C15,
`index` C3, `create` C1/C6/C22, `registry` C19, `gitignore` C19/C21, `log`
log.md. Held back: reported as without `--fix`.

| Flag | Effect |
|---|---|
| `--preflight` | No writes; `plan[]`; exit 0 unless `--fail-on` |
| `--fix-only C,...` | Only these; implies `--fix` |
| `--no-quarantine`, `--no-log` | Drop that class |
| `--refuse-on C,...` | One would act: exit 2, no writes |

The plan reads the tree as it is: a repair that only becomes necessary after an
earlier repair is not listed, and under `--refuse-on` it is refused when
reached, after earlier classes have written.

## Severity

- **Critical**: broken functionality (missing indexes, wrong placement, bad frontmatter,
  privacy)
- **Warning**: inconsistency (dead links, bad sources, stale dates)
- **Suggestion**: improvement (coverage, connections, migrations)
- **Info**: never fails a wiki

## Whole-tree checks

C4 reads `wiki/` and `inventory/`; `links check` covers the rest of a tree,
`lint --all` every hub root.

## Placement map (C11)

First match wins: `type: thesis` goes to `wiki/theses/`; raw `type` of `articles`,
`papers`, `repos`, `notes`, `data` goes to `raw/<type>/`; wiki `category` of
`concept`, `topic`, `reference` goes to `wiki/concepts|topics|references/`;
inventory `kind` goes to `items`, `ideas`, `candidates`, `entities` or `corpora`.
A file with both `category` and `type` is an article. Not placed:
`output/projects/` (C8/C9). Layout and allowlists: `wiki-structure.md`.

## Alias tables (C13)

Append-only; never remove an entry. Empty today, so alias rewriting is a no-op.
Form: `old_key -> canonical_key`, `old_value -> canonical_value (for field: F)`.

Canonical optional raw keys (not unknown): `collection`, `adapter`,
`upstream_id`, `upstream_type`, `revision`, `sha`, `canonical_url`,
`content_format`, `license`, `authors`, `categories`, `outlinks`, `fetched`,
`inbox_item`, `research_*`, `credibility_*`.

## C8c: legacy `_project.md` to `WHY.md` (CLI, with `--fix`)

`llm-wiki project migrate-why [--apply] --json` is the rule: lossless (title
and goal from frontmatter, derived Members sections dropped, the rest kept in
order), idempotent once `WHY.md` exists, never a placeholder goal. Preview it,
then `--apply` with `--fix`; report each `Migrated ... (preserved N sections)`.

## Semantic passes

- **Coverage**: group the CLI's uncovered and orphan findings by topic,
  recommend compile, `See Also` link or backlog, and name the articles that
  should link. A backlog entry is not a synthesized source.
- **Freshness**: rank flagged articles by `freshness score`; warn for hot and
  warm, info for cold.
- **Deep**: cite what a search found; never rewrite bodies.

## Fix review

Apply only unambiguous fixes. Never rewrite bodies, create `WHY.md`
placeholders, move files into projects, convert outputs to inventory or dataset
records, delete unknown directories, create an absent inventory or dataset tree,
resolve slug or archive collisions, add `compiled-from: conversation`, or move a
topic in or out of the archive.

## Report

Lead with plain English, not a check code (it may trail in parentheses).

```markdown
## Wiki Lint Report - YYYY-MM-DD
### Summary  (checks run, critical/warnings/suggestions, auto-fixed)
### Critical Issues / Warnings / Suggestions  (description - path)
### Coverage  (uncovered sources, broken links, missing See Also)
### Projects and Candidates  (missing WHY.md, stale, migrated, groupings)
### Inventory and Datasets  (counts, schema issues)
### File Placement and Schema  (moves old -> new, quarantined files)
### Archive  (checked topics, registry repairs, collisions)
```

## Rationale

Lint is the migration (no `wiki migrate`). When a structure or field changes,
update the CLI check, its row here and the fixture; every wiki self-heals on its
next lint. Rename a directory: C11/C12, allowlists. Rename a field or enum value: append an alias, never remove one. Add a required
field: C2, with an inference rule or default. Project model changes touch
C8/C9 and `projects.md`. Inventory, dataset and archive layers are lazy: absent is
a suggestion, partial is repairable, conversions stay human-gated.
