# Linting Rules

Lint is CLI-first. `llm-wiki lint --json` is the source of truth for every check
marked **CLI** below; the agent runs it first and spends judgment only on the
rows marked **agent** and on reviewing what `--fix` proposes. Exact flags are in
[cli.md](cli.md).

## Running the CLI

```bash
llm-wiki lint --json [<wiki-root> | --local | --wiki <slug>] [--hub <path>] \
  [--private | --public] [--include-archived] [--fix] \
  [--fail-on critical|warning|suggestion] [--strict-engine]
```

- `--fail-on` sets the lowest severity that exits non-zero (default
  `suggestion`, any finding). `--strict-engine` turns declared-versus-running
  engine drift from a warning into critical. `--include-archived` is required to
  lint an explicitly targeted archived topic.
- The report holds `status`, `counts`, `fixes` and `issues[]` (`check`,
  `fix_class`, `severity`, `message`, `path`, `fixable`). `check` is the id of
  the row below that found the issue; match findings by `check` and `path`, not
  by message.
- Exit non-zero with JSON means findings met `--fail-on`. Exit non-zero without
  JSON is a CLI error (unresolved or archived wiki, bad flags).

## Fix classes

Classes: `quarantine` C12, `placement` C11, `frontmatter` C2/C4b/C6/C15,
`index` C3, `create` C1/C6/C22, `registry` C19, `gitignore` C19/C21, `log`
log.md. Held back: reported as without `--fix`.

| Flag | Effect |
|---|---|
| `--preflight` | No writes; `plan[]`; exit 0 unless `--fail-on` |
| `--fix-only C,...` | Only these; implies `--fix` |
| `--no-quarantine`, `--no-log` | Drop that class |
| `--refuse-on C,...` | One would act: exit 2, no writes |

The plan reads the tree as it is: a repair that only becomes necessary once
an earlier repair has run is not listed, and under `--refuse-on` it is
refused when reached, after earlier classes have written.

## Severity

- **Critical**: broken functionality (missing indexes, wrong placement, corrupted
  frontmatter, privacy failure)
- **Warning**: inconsistency (dead links, unresolved sources, stale dates)
- **Suggestion**: improvement opportunity (coverage, connections, migrations)
- **Info**: adoption prompts that never fail a wiki

## Whole-tree checks

C4 reads `wiki/` and `inventory/`; `links check` covers the rest of a tree and
`lint --all` every hub root.

## Placement map (C11)

First match wins: `type: thesis` goes to `wiki/theses/`; raw `type` of `articles`,
`papers`, `repos`, `notes`, `data` goes to `raw/<type>/`; wiki `category` of
`concept`, `topic`, `reference` goes to `wiki/concepts|topics|references/`;
inventory `kind` goes to `items`, `ideas`, `candidates`, `entities` or `corpora`.
A file with both `category` and `type` is an article. Out of scope:
`output/projects/` (C8/C9). Layout and allowlists live in `wiki-structure.md`;
the CLI holds the enforced allowlists.

## Alias tables (C13)

Append-only; never remove an entry. Empty today, so alias rewriting is a no-op.

```
# Key aliases:    old_key  ->  canonical_key
# Value aliases:  old_value  ->  canonical_value  (for field: <field>)
```

Canonical optional raw keys (not unknown): `collection`, `adapter`,
`upstream_id`, `upstream_type`, `revision`, `sha`, `canonical_url`,
`content_format`, `license`, `authors`, `categories`, `outlinks`, `fetched`,
`inbox_item`, `research_query`, `research_agent`, `research_session`,
`credibility_score`, `credibility_tier`.

## C8c: legacy `_project.md` to `WHY.md` (agent, with `--fix`)

Critical and lossless. Take `goal` and `title` from the frontmatter. Drop only
derived sections (inside `<!-- DERIVED -->` markers, or headed `## Members` /
`## External Members`); keep every other section verbatim, in order. If the body
has no `## Goal` section, put the frontmatter goal as the first paragraph. Write
`# <title>` plus the kept sections to `WHY.md`, delete `_project.md`, and report
`Migrated <slug>/_project.md -> <slug>/WHY.md (preserved N sections)`. Idempotent
once `WHY.md` exists. Never create `WHY.md` with a placeholder goal (C8a warns
only).

## Semantic passes

- **Coverage**: take the CLI's uncovered and orphan findings, group by topic,
  recommend compile, `See Also` link, or backlog, and name the articles that
  should link. Do not claim a backlog entry means the source is synthesized.
- **Freshness**: score each flagged article (standard four dimensions, or the
  rebased two for `compiled-from: conversation`), scale decay by volatility,
  flag below threshold. Warn for hot and warm, info for cold.
- **Project candidates (C9d)**: slug is the longest common prefix of three or
  more files, minus dates, `-vN`, `-final`, and `article-`/`output-`/`report-`;
  under 4 characters means no proposed slug.
- **Deep**: cite what a search found; never rewrite article bodies.

## Fix review

Apply only unambiguous fixes. Never: rewrite article bodies, create `WHY.md`
placeholders, move files into projects, convert outputs to inventory or dataset
records, delete unknown directories, create an absent inventory or dataset tree,
resolve slug or archive collisions, add `compiled-from: conversation`, or move a
topic in or out of the archive (that is `wiki archive`).

## Report

Lead each line with plain English, never a check code; a code may trail in
parentheses.

```markdown
## Wiki Lint Report - YYYY-MM-DD
### Summary  (checks run, critical/warnings/suggestions, auto-fixed)
### Critical Issues / Warnings / Suggestions  (description - path)
### Coverage  (uncovered sources, broken links, missing See Also, new connections)
### Projects and Candidates  (active/archived, missing WHY.md, stale, migrated, groupings)
### Inventory and Datasets  (counts, schema issues, migration candidates)
### File Placement and Schema  (moves old -> new, quarantined files, alias rewrites)
### Archive  (skipped or checked topics, registry repairs, collisions)
```

## Rationale

Lint is the migration: there is no `wiki migrate` command. When the canonical
structure or a frontmatter field changes, update the CLI check, the matching
row here, and the fixture, so every wiki self-heals on its next lint. Rename a
directory: update C11/C12 and the allowlists. Rename a field or enum value:
append an alias, never remove one. Add a required field: add it to C2 with an
inference rule or default. Project model changes touch C8/C9 and `projects.md`.
Inventory, dataset and archive layers are lazy: an absent tree is a suggestion,
a partial tree is repairable, conversions stay human-gated.
